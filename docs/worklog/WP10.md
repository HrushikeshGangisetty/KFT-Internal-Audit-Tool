# WP10 — Tasks and daily progress (minimal), with Home and navigation rework
Agent: Claude Code    Branch: main    Date: 20 October 2026

The user authorised WP10 plus an additional UI scope (role-aware Home, grouped navigation, mobile, consistent tags), with a direct commit and push to main. No deployment, shared-data changes or real email are part of this session.

## Done

### Backend (WP10)
- New `tasks` app (`fcops/backend/tasks/`): `Task(title, description, accountable_user, department?, priority, due_date?, status ∈ planned/in_progress/blocked/done/cancelled, issue?, fc?, created_by)`, `TaskCollaborator`, and `DailyUpdate(task?, author, date, progress, next_step, blockers, supersedes?, created_at)`. Migration `tasks/0001_initial.py` (new tables only).
- **Daily-update approach chosen:** append-only rows. `save()` refuses updates and `delete()` raises; the API has no update/delete route. A correction is a new row with `supersedes`, allowed only for the author's own update, the same working-calendar day, the same task, and once per row. Earlier days cannot be superseded, so yesterday's text never changes. "Today" is the date in `WORKING_TIMEZONE`, set by the server, never the client.
- Scope in `access/policy.py`: `visible_tasks` (own + collaborative; every head and the manager see all; admins get nothing by default) and `visible_daily_updates` (own, or on a visible task). `TASKS_TEAMMATES_VISIBLE` (default `False`) is a PLACEHOLDER setting until the PRD decision. Audit entries for `Task` now follow task scope rather than the "visible to all staff" bucket.
- Writes go through `tasks/services.py` inside transactions with audit: people create tasks for themselves; only a head/manager may assign or reassign to others; only the accountable person or a head/manager may change a task; only participants may post updates on a task. Linked issue/FC IDs are validated through scoped fields on input and hidden on output from readers who cannot see them.
- APIs: `/api/tasks/` (list/detail/create/patch, `?mine=1`, `?open=1`, `POST /collaborators/`, no delete), `/api/daily-updates/` (list/detail/create only, `?current=1`, `?mine=1`), `GET /api/progress/?department=` (heads/manager only): assigned work, no update today, overdue, blocked, today's updates with next steps and blockers, unacknowledged-past-target and escalated issues. Plain lists, no activity counts or rankings.
- `GET /api/me/queue/` now also returns `tasks` (my open tasks), `updated_today`, and `ack_due_at` on issue rows.
- `/api/auth/me/` gains display-only flags `is_head_or_manager`, `can_view_fcs`, `can_register_fc` computed from `access.policy`; endpoints still enforce scope. No access rule changed.

### Frontend (UI scope)
- `pages/Dashboard.jsx` → `pages/Home.jsx`: quick actions (Report a problem, Find an FC / serial, New FC only with `can_register_fc`), My queue (I own / To acknowledge with one-tap Acknowledge / Handoffs with Accept/Reject / Tasks, plus today's update status), Needs attention for heads/manager (unacknowledged past target, escalated, blocked tasks, blocked FCs, no update today), Recent activity and condensed FC pipeline. Each panel loads independently with its own skeleton, empty state and error banner (`usePanel`/`Panel` in `components/ui.jsx`); panels a role cannot use are not requested.
- New pages: `Queue.jsx` (My queue), `Tasks.jsx` (my/all tasks, status change, new task, today's update, Team progress for heads), `Report.jsx` (quick FC-less report on the existing WP4 `POST /api/issues/report/`).
- Sidebar grouped by purpose and data-driven in `App.jsx`: Work (Home, My queue, Issues, Tasks), Hardware (FCs, Test & evidence, Firmware, Software updates; hidden without FC access), Knowledge (Known issues, Search, Activity log), Admin (Test configuration, FC models, Accounts). Empty groups are hidden.
- Shared `UrgencyTag`, `OwnerTag`, `DueTag`, `ago()` used on Home, Issue list, Issue detail and FC detail issue table; task statuses added to the status tone map.
- Mobile: at ≤600px one column, 44px minimum touch targets; queue rows wrap rather than scroll.
- Fixed in passing: Issue detail linked FC-less issues to `/fcs/null`; FC list now honours `?search=` and `?current_stage=` from Home.

## Decisions and limitations

- Release link on `Task` deferred until WP11 creates the release model.
- Teammate visibility is the PLACEHOLDER flag above, default off, per PRD §3.
- "No update today" lists every active department member, including the manager and the account admin when they hold memberships; whether updates are mandatory and for whom is still open (PRD §9).
- `/api/progress/` with a department filter lists members by active membership and tasks by department or accountable member. Acknowledgement-due is computed per issue in Python (`ponytail:` note); fine at pilot volume.
- The existing "report form" (`IssueCreate`) requires an FC, so "Report a problem" uses a new quick form on the existing WP4 report endpoint. `IssueCreate` remains for FC lifecycle issues from FC detail.
- The previous manager analytics (averages, by-department meters, time in stage, reworks) were removed from Home; `/api/dashboard/summary/` is unchanged.
- One failing panel not blanking the page is by construction (per-panel loading/error state); no fault was injected in the browser to demonstrate it.
- Handoff rejection reason uses a browser prompt; acceptable for the pilot, not polished.
- No new dependencies. No Graphify graph exists at the workspace or `fcops/` root; no graph update was applicable.
